# АльфаКредит — кабинет предпринимателя

React + TypeScript приложение для хакатона. Новый путь: **Потребность → Рекомендация → Проверка → Заявка → Решение → Договор → Подписание → Выдача**. Рекомендации подключены к `POST /api/financing/preview`, контракт **v2 от 24.10.2026**.

## Запуск в WebStorm

Node.js 24 и npm. Откройте эту папку как проект и выполните:

```bash
npm ci
npm run dev
```

Обычно Vite открывает `http://localhost:5173`. Для настоящего локального API создайте `.env.local`:

```dotenv
VITE_API_BASE_URL=http://localhost:8080
```

Перезапустите Vite. Пустое значение включает мок. API-режим всегда использует бэкенд: при сетевой ошибке подмена моками не происходит. Вход на тестовом стенде: `client_good` / `Demo123!`. Пароль не сохраняется; JWT хранится в `sessionStorage`, выход очищает сессию и черновик текущего пользователя.

## Что реализовано

- Интерфейс для компьютера: закреплённая боковая навигация, таблица сравнения, белая сводка выбранного кредита и состав общей выплаты. Ссылка cookie находится в одной строке футера. Переходы, смена статуса, раскрытие и закрытие блоков анимированы; после успешной подписи страница плавно возвращается к текущему статусу. При `prefers-reduced-motion` анимации и плавная прокрутка отключены.
- Три шага оформления с сохранением черновика в пределах вкладки. Единственная компания выбирается автоматически. При истечении авторизации повторный вход тем же пользователем восстанавливает введённое; другой пользователь не получает чужой черновик.
- Сумма сразу группируется пробелами (`1 500 000`), при наборе, вставке и редактировании сохраняется положение курсора. В запрос уходит число `1500000`. Общий компонент используется и в каталоге.
- Дата, к которой нужны деньги, отделена от срока возврата. `needByDate` передаётся строкой `YYYY-MM-DD`, без преобразования в UTC; «сегодня» проверяется по Москве.
- Основная рекомендация и максимум одна альтернатива. Показываются ставка, платёж, общая выплата, переплата, ориентир получения и объяснения из API. Все условия предварительные, оговорка сервера видна пользователю.
- Срок можно изменить; перерасчёт запускается после короткой паузы. Старый запрос отменяется, а его запоздавший ответ игнорируется. Продолжение с неактуальным расчётом недоступно.
- `InsufficientData` отображается как отсутствие оценки; nullable-поля не заменяются нулями или 10 % выручки. `suggestedAmount` запускает новый расчёт, а не создаёт заявку.
- `notCompared` показывает овердрафт и кредитную линию отдельно, со ссылкой на обычную форму каталога. `unsuitable` содержит причины и предложения меньшей суммы из API.
- Preview и переходы между шагами не создают заявку. Только последний шаг отправляет актуальный `applyWith` в `POST /api/applications`. Повторное нажатие блокируется; автоматического повтора POST после сетевой ошибки нет.
- Карточка показывает «Запрошено / Одобрено», причины изменения условий, фактическую ставку, платёж, общую выплату и переплату из оффера, дату потребности и историю. Старые заявки без даты поддерживаются.
- Договор, график платежей, печатная форма с JWT, код подтверждения, подпись и ожидание выдачи. Полученный `demoCode` выделен в блоке с кнопкой «Вставить демо-код»; настоящий SMS не отправляется. После перезагрузки код можно запросить заново.
- Фоновое обновление во время обработки, ManualReview, подписания и выдачи. Смоделированное решение менеджера явно отмечено. По завершении опрос останавливается.
- Демонстрационное уведомление о cookie и хранении данных. Его текст не заменяет политику обработки данных рабочего сервиса.

## Маршруты

| Адрес | Назначение |
|---|---|
| `/` | Переход к потребности |
| `/financing/need` | Цель, сумма, нужная дата |
| `/financing/recommendation` | Подбор, сравнение и перерасчёт срока |
| `/financing/review` | Компания и условия перед окончательной отправкой |
| `/catalog?product=overdraft` | Обычная форма, продукт можно выбрать заранее |
| `/applications` | Мои заявки |
| `/applications/:id` | Решение, предложение, договор и выдача |

## Бэкенд и интеграция

Базовый backend: [GatheredSatyr53/probiinik](https://github.com/GatheredSatyr53/probiinik), подключён коммит `a65acd3` от 25 октября 2026: preview v2, итоговая стоимость предложения и предварительный платёж в каталоге. Перед запуском обновите бэкенд и пересоберите его:

```bash
git pull --ff-only
docker compose up -d --build
```

`http://localhost:8080/health/ready` должен отвечать `Healthy`. Относительно старой локальной версии применяется уже существующая миграция `AddApplicationNeedByDate`; база не удаляется. Скоринг теперь использует образ ML-команды из GHCR. Для preview новые переменные Compose/.env не нужны. `ALFACREDIT_TEST_POSTGRES` относится только к интеграционным тестам бэкенда, фронтенду не требуется.

**Стоимость итогового предложения:** в API `0e977df` поля `offer.totalPayment` и `offer.totalInterest` уже есть. На реальном локальном API проверены 1 663 116,74 ₽ общей выплаты и 163 116,74 ₽ переплаты для 1 500 000 ₽ на 12 месяцев под 19,5 %; суммы предложения и договора совпали. Фронт получает их с сервера, отдельно от preview, и сохраняет совместимость со старым API без этих полей.

**Лимитные продукты:** в коммите бэкендера `ebedeb8` исправлены `offer.totalPayment` и `offer.totalInterest`: для овердрафта и кредитной линии теперь `null`. В каталоге `preliminaryPayment.available=false`, причина `limit_product`; фронт показывает причину без выдуманного платежа.

**Платёж в каталоге:** при заполнении суммы и срока фронт вызывает `GET /api/products?amount=1500000&termMonths=12` и показывает `preliminaryPayment.monthlyPayment` в карточке выбранного продукта. Запросы выполняются с задержкой 300 мс, старые ответы игнорируются; есть загрузка и повтор после ошибки. Без суммы или срока запрос не отправляется. В демо используются фиксированные JSON-примеры, клиентского расчёта процентов нет.

| Действие | Запрос |
|---|---|
| Вход | `POST /api/auth/login` |
| Компании / продукты | `GET /api/companies`, `GET /api/products` |
| Предварительный подбор | `POST /api/financing/preview` |
| Создание / список / карточка | `POST /api/applications`, `GET /api/applications`, `GET /api/applications/{id}` |
| Ответ на предложение / отмена | `POST /api/applications/{id}/offer/accept`, `/offer/decline`, `/cancel` |
| Договор / HTML-документ | `GET /api/applications/{id}/contract`, `/contract/document` |
| Код / подпись | `POST /api/applications/{id}/contract/sign/request-code`, `/contract/sign` |

Защищённые запросы отправляют `Authorization: Bearer <JWT>`. HTTP и обработка ProblemDetails вынесены в `src/api/`; типы preview — `src/types/financing.ts`, заявки — `src/types/api.ts`. При `401` требуется вход; `400` показывает ошибки полей, `403` — отсутствие доступа, `409` обновляет карточку после конфликта действия.

## Полная проверка через браузер

1. В API-режиме войдите как `client_good` / `Demo123!`. Выберите оборотные средства, укажите 1 500 000 ₽ и будущую дату в пределах двух лет.
2. Получите рекомендации, измените срок (например, с 12 на 18 месяцев), убедитесь, что платёж и переплата обновились. Вернитесь назад — сумма и дата сохраняются.
3. Проверьте компанию и условия, затем отправьте заявку. До этого заявка не создана.
4. Дождитесь решения, сравните запрошенные и одобренные параметры и фактическую стоимость. Примите предложение.
5. Посмотрите график и печатную форму. Получите код: при стандартном `CONTRACTS_REVEAL_CODE=true` его вернёт демо-API. Проверьте неверный код, затем нажмите «Вставить демо-код» и подпишите договор.
6. Дождитесь выдачи, проверьте сумму, счёт, дату и платёжное поручение. Перезагрузите страницу и откройте заявку из списка.

`client_manual` позволяет проверить автоматический ответ демо-менеджера; `client_new` — отсутствие подходящих вариантов. `InsufficientData` проверяется отдельной фикстурой, поскольку в стандартном seed нет компании без прибыли и расходов. Все реквизиты и выдача на стенде демонстрационные, реальные средства не переводятся.

## Мок и ограничения

Без адреса API доступен фиксированный пример v2 из публичной документации: 1 500 000 ₽, пополнение оборотных средств, 12 месяцев. Стоимость в моках не рассчитывается на клиенте; для других параметров показывается предложение подключить API. Это ограничение мока не относится к API-режиму.

Обычная форма каталога в мок-режиме сохраняет введённые заявки в `localStorage`. Мок не моделирует банковское решение; полную обработку проверяйте через бэкенд. Методы договора/кода/подписи работают для демо-заявки с подготовленным предложением.

Оформление основано на согласованном варианте «Деловой кабинет», со светлой сводкой условий. Мобильная версия не входит в текущую задачу. Даты графика договора, вычисляемые бэкендом от UTC, в рамках этой задачи не менялись.

## Проверки и Docker

```bash
npm test
npm run build
git diff --check
```

```bash
docker build --build-arg VITE_API_BASE_URL=http://localhost:8080 -t alfacredit-frontend:api .
docker run --rm -p 3000:8080 alfacredit-frontend:api
```

Приложение открывается на `http://localhost:3000`, nginx слушает **8080 внутри контейнера**. Прямые ссылки на шаги и заявки поддерживаются. `VITE_API_BASE_URL` задаётся при сборке и должен быть доступен браузеру; при изменении адреса пересоберите образ. Для образа с моками опустите build-arg.

`.env.local`, `node_modules`, `dist`, файлы WebStorm и результаты локальных проверок в репозиторий не входят.
