# АльфаКредит — фронтенд прототипа

React + TypeScript приложение с тремя экранами: форма новой заявки (`/`), список «Мои заявки» (`/applications`) и карточка заявки (`/applications/:id`). По умолчанию работает браузерный JSON-мок: заявки сохраняются в `localStorage` и не отправляются в API. При заданном `VITE_API_BASE_URL` включается реальный локальный бэкенд.

## Что реализовано

- Вход тестового клиента для API-режима; JWT хранится только в `sessionStorage`, пароль не сохраняется.
- Форма с выбором компании, продукта, суммы, срока и цели. Проверяются обязательные поля, отрицательная и выходящая за границы продукта сумма, а также некорректный срок.
- Список заявок с переходом к карточке и постраничной загрузкой.
- Карточка заявки с номером, ID, введёнными сведениями, текущим статусом, следующим действием и историей. Для решения банка показывает причины отказа или изменения условий, одобренную сумму, срок, ставку, ежемесячный платёж и срок действия предложения.
- Кнопки принятия, отклонения предложения и отмены заявки появляются только по `availableActions`. Во время запроса повторное нажатие блокируется; после ответа карточка обновляется. Ошибка `409` вызывает загрузку актуальной карточки.
- В API-режиме карточка обновляется каждые 2,5 секунды во время обработки и пока предложение ожидает ответа. При ошибке карточка остаётся видимой и доступен повтор запроса.
- Состояния загрузки, успешного сохранения и ошибок с возможностью повторить запрос.
- Отдельные TypeScript-типы для продукта, заявки, входа и ошибок API; HTTP-запросы и JSON-мок вынесены из компонентов.
- После принятия предложения: договор, условия, график платежей и печатная HTML-форма, загружаемая с JWT. Документ можно просмотреть, распечатать и скачать.
- Запрос и ввод шестизначного кода подписи, срок действия и оставшиеся попытки. `demoCode` явно помечен как имитация SMS и хранится только в состоянии открытой страницы.
- После подписи — ожидание выдачи и результат с суммой, счётом, датой и номером платёжного поручения. `ManualReview`, `ContractSigning` и `Signed` продолжают обновляться; терминальные статусы останавливают опрос. `decision.isSimulated` отмечает смоделированное решение менеджера.
- В числовых полях удаляются буквы при наборе и вставке, знаки, дроби и экспоненциальная запись отклоняются. Проверка обязательности и границ продукта сохраняется.
- Демонстрационное уведомление о cookie и хранении данных с сохранением выбора и повторным открытием через «Cookie и данные». Это заглушка текста, политика рабочего сервиса ещё не опубликована.

Связанный бэкенд команды: [GatheredSatyr53/probiinik](https://github.com/GatheredSatyr53/probiinik).

## Разработка в WebStorm

Откройте эту папку как проект WebStorm. Требуется Node.js 24 и npm. В терминале проекта:

```bash
npm ci
npm run dev
```

Vite покажет локальный адрес (обычно `http://localhost:5173`). Для проверки:

```bash
npm test
npm run build
npm run preview
```

`npm run preview` запускает собранную версию. Чтобы увидеть состояние ошибки сохранения, создайте `.env.local` со строкой `VITE_MOCK_ERROR=true` и перезапустите `npm run dev`. Для обычного сценария удалите эту строку или установите `false`.

## Запуск с локальным бэкендом

1. Обновите отдельный репозиторий бэкенда (`git pull --ff-only`), запустите `docker compose up -d --build` и убедитесь, что `http://localhost:8080/health/ready` отвечает успешно. Для полного пути нужен бэкенд с `docs/completion-flow.md` (интеграция проверяется на `b161c41`). Существующий образ нужно пересобрать после обновления исходников.
2. Создайте в корне фронтенда `.env.local`:

   ```dotenv
   VITE_API_BASE_URL=http://localhost:8080
   ```

3. Перезапустите `npm run dev` и откройте `http://localhost:5173`. Введите тестовые данные клиента из README бэкенда (`client_good` / `Demo123!`). После входа форма берёт продукты и компанию из API. Список, создание, карточка и действия по заявке работают через API.

Пароль не сохраняется; JWT хранится в `sessionStorage` до закрытия вкладки или истечения срока. Выход очищает сессию. Если API недоступно, верните пустое значение `VITE_API_BASE_URL` и перезапустите Vite — останется демо-режим.

## Демо-сценарий

1. Откройте форму, выберите ООО «Ромашка» и «Оборотный кредит».
2. Укажите 1 500 000 ₽, срок 12 месяцев и цель «Пополнение оборотных средств».
3. Нажмите «Отправить заявку». Откроется карточка с номером, сведениями, статусом и следующим шагом.
4. Откройте «Мои заявки» и вернитесь в созданную карточку: в демо-режиме она загрузится из `localStorage`, в API-режиме — из бэкенда после входа.
5. Для проверки валидации попробуйте пустую форму, нулевую сумму и срок 30 месяцев для «Оборотного кредита».

Демо-данные продуктов и компании соответствуют примерам бэкенда. Они находятся в `src/api/mockData.ts`. Хранилище и имитация задержки/ошибок — в `src/api/mockCreditApi.ts`. Демо-заявка остаётся в статусе «Отправлена» до её отмены: решение банка и предложение в браузере не рассчитываются. Для проверки предложения используйте актуальный бэкенд. Формат запросов и ответов описан в `src/types/api.ts`, интерфейс источника данных — в `src/api/creditApi.ts`.

### Полный путь с API

Создайте заявку под `client_good` / `Demo123!`: «Оборотный кредит», 1 500 000 ₽, 12 месяцев, пополнение оборотных средств. Дождитесь решения, примите предложение, изучите договор и график, откройте печатную форму. Нажмите «Получить код»: при `CONTRACTS_REVEAL_CODE=true` бэкенд вернёт демонстрационный код, который интерфейс покажет с пометкой об имитации. Введите сначала неверные 6 цифр, проверьте ошибку и уменьшение попыток, затем верный код. После подписи дождитесь выдачи; обновите страницу и снова откройте заявку из списка.

Для ручного рассмотрения используйте `client_manual`, 8 000 000 ₽, 24 месяца, «Оборотный кредит». Демо-менеджер отвечает автоматически после задержки, исход зависит от настроек стенда. `DEMO_MANAGER_APPROVAL_PROBABILITY=0` гарантирует отказ, `1` — одобрение; после изменения переменной пересоздайте API через Compose. Такие решения помечаются как смоделированные. Настоящие средства на стенде не переводятся.

Мок поддерживает чтение договора, запрос кода `123456`, ошибки и подпись, если в сохранённой демо-заявке уже есть предложение. Он не заменяет банковское решение и реальную интеграционную проверку. Новые nullable-поля заявки: `contract`, `disbursement`; полная структура договора и график загружаются отдельным запросом. После перезагрузки запрошенный код и попытки восстанавливаются из API, сам `demoCode` повторно не раскрывается: можно запросить новый код.

## API-контракт

Экранные компоненты обращаются только к `CreditApi`. Переключение мок/HTTP находится в `src/main.tsx`, вход и хранение JWT — в `src/api/httpAuthApi.ts`, запросы заявок — в `src/api/httpCreditApi.ts`.

| Действие | Запрос | Особенность |
|---|---|---|
| Вход | `POST /api/auth/login` | Получить JWT для следующих запросов. |
| Продукты | `GET /api/products` | Публичный список. |
| Компании | `GET /api/companies` | Заголовок `Authorization: Bearer <JWT>`. |
| Создание заявки | `POST /api/applications` | JWT, тело `CreateApplicationRequest`; ответ `201` с `id`. |
| Карточка заявки | `GET /api/applications/{id}` | JWT, полное тело `Application`. |
| Мои заявки | `GET /api/applications?page=1&pageSize=20` | JWT, список заявок клиента. |
| Принять предложение | `POST /api/applications/{id}/offer/accept` | JWT, без тела; возвращает обновлённую заявку. |
| Отклонить предложение | `POST /api/applications/{id}/offer/decline` | JWT, без тела; возвращает обновлённую заявку. |
| Отменить заявку | `POST /api/applications/{id}/cancel` | JWT, без тела; возвращает обновлённую заявку. |
| Получить договор | `GET /api/applications/{id}/contract` | JWT, стороны, условия, подпись и график. |
| Печатная форма | `GET /api/applications/{id}/contract/document` | JWT, HTML загружается как Blob и открывается в изолированном iframe. |
| Получить код | `POST /api/applications/{id}/contract/sign/request-code` | JWT, без тела; срок, попытки и nullable `demoCode`. |
| Подписать договор | `POST /api/applications/{id}/contract/sign` | JWT, `{ "code": "123456" }`; обновлённая заявка `Signed`. |

Ошибку `400` с `errors: { поле: [сообщение] }` форма показывает рядом с соответствующими полями. При `401` интерфейс возвращает пользователя на экран входа. Для запросов из браузера нужен доступный браузеру URL, а не внутреннее имя сервиса Docker. Стандартный CORS бэкенда разрешает `http://localhost:5173` и `http://localhost:3000`; если фронтенд открыт с другого адреса, добавьте origin в `CORS_ORIGINS` бэкенда.

Поля `decision` и `offer` могут быть `null`, пока банк обрабатывает заявку. Карточка показывает условия только из `offer`; скоринг и проверки клиенту не показываются. Действия доступны по массиву `availableActions` из ответа API.

Ошибки подписи `400` показываются у ввода кода. После ошибки подписи карточка перечитывается для актуальных попыток и статуса; `409` может означать просроченный код, исчерпанные попытки или уже изменившийся статус. `401` возвращает к входу. Во время любого изменения заявки кнопки изменения блокируются общей блокировкой, устаревший ответ фонового опроса не заменяет результат действия. При ошибке выдачи интерфейс показывает причину и продолжает обновлять статус. Если задержка сохраняется, предлагается обратиться в банк.

Контракт бэкенда: https://github.com/GatheredSatyr53/probiinik/blob/main/docs/api.md

## Структура проекта и проверки

| Путь | Назначение |
|---|---|
| `src/features/application/` | Форма, список, карточка и валидация. |
| `src/features/auth/` | Вход в API-режиме. |
| `src/api/` | Интерфейс источника данных, HTTP-адаптеры и моки. |
| `src/types/api.ts` | Типы запросов и ответов. |
| `src/App.tsx`, `src/main.tsx` | Навигация и выбор режима. |

`npm test` запускает проверки формы, списка, карточки, действий, моков, входа и HTTP-запросов. `npm run build` проверяет TypeScript и собирает статический фронтенд. Файлы `.env.local`, `node_modules`, `dist` и настройки WebStorm в репозиторий не входят.

## Docker

```bash
docker build -t alfacredit-frontend .
docker run --rm -p 8081:8080 alfacredit-frontend
```

После запуска приложение доступно на `http://localhost:8081`. `nginx.conf` возвращает `index.html` для маршрутов списка и карточки, поэтому прямые ссылки работают после обновления. По умолчанию образ использует мок. Сам API в образ фронтенда не входит.

Для API-режима с запущенным бэкендом используйте разрешённый в его CORS порт 3000:

```bash
docker build --build-arg VITE_API_BASE_URL=http://localhost:8080 -t alfacredit-frontend:api .
docker run --rm -p 3000:8080 alfacredit-frontend:api
```

Откройте `http://localhost:3000`. `VITE_API_BASE_URL` встраивается при сборке Vite: это адрес бэкенда **для браузера пользователя**, а не адрес внутри контейнера. При смене адреса соберите образ заново.
